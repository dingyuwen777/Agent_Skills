# Research

Research 的目标不是“搜很多”，而是为当前问题取得**足够新、足够可靠、可追溯且真正会影响结论的证据**。

核心链路：

```text
定义研究问题与时间范围
→ 判断哪些事实必须外部核验
→ 默认寻找当前最新适用资料
→ 一手 / 权威来源优先
→ 必要时多源交叉核验
→ 核对发布日期 / 事件日期 / 版本 / 适用范围
→ 处理来源冲突和不确定性
→ 把事实与分析分开
→ 用来源支持关键当前事实
→ 新搜索不再改变结论时停止
```

## 1. 什么时候应研究

出现下面任一情况时优先取得外部当前证据：

- 用户问“最新 / 当前 / 今天 / 最近 / 现在”；
- 事实可能随时间变化：产品、价格、政策、标准、API、软件版本、组织人员、公司数据、体育、新闻等；
- 主题陌生、专业、细分或容易记错；
- 用户要求来源、引用、论文、财报、标准、官方文档或深度调研；
- 事实错误会显著影响安全、法律、财务、健康、工程实施或业务判断；
- 多个来源存在明显争议，需要核验。

## 2. 默认时效规则

**除非用户明确要求历史资料、旧版本、指定时间点，或明确禁止联网，否则研究以当前最新且适用的资料为默认目标。**

“最新”不是只看搜索排序。必须尽量核对：

- 发布 / 更新时间；
- 事件实际发生时间；
- 软件 / 标准 / 报告版本；
- 适用地区、人群、产品或时间范围；
- 是否已被更新、撤回、替代或失效。

历史问题保留历史语境，不用今天的状态覆盖过去。

## 3. 来源质量

优先顺序不是机械排名，而是按问题选择最接近事实生产者的来源：

1. 官方文档、标准、法规、原始数据库、公司公告/财报、论文原文等一手资料；
2. 高质量二手资料，用于解释、交叉核验和发现争议；
3. 社区、论坛、社媒，用于经验、用户反应和线索；不能单独承担需要权威证明的事实。

重要结论若来源本身存在利益关系、内容含糊或事实影响重大，应增加独立来源。

## 4. 事实、分析与不确定性

- 来源直接支持的内容写成事实；
- 跨来源归纳写成分析；
- 对动机、因果、未来结果等没有直接证据的内容不得伪装成事实；
- 来源冲突时说明谁在什么时间、版本、范围下说了什么，以及为什么采用或暂不采用其中一个结论；
- 没找到可靠证据就明确说没有验证，不用模型记忆补齐。

## 5. 回答方式

先回答用户的问题，再给支持关键结论所需的来源。不要先写长篇“研究过程”。

如果研究结果还需要比较、决策或方案设计，在证据取得后进入 [Analysis](../analysis/SKILL.md)；不能让推理替代缺失的当前事实。

## 7. 失败边界

- 无法联网或关键来源不可访问：明确哪些当前事实未验证，不把旧知识说成已核实。
- 搜索结果只有转述：继续找原始来源；找不到时降低结论强度。
- 当前来源相互冲突：保留冲突并解释证据，不为得到单一答案强行平均。
- 用户明确要求不要联网：遵守，并把时效限制写清楚。
