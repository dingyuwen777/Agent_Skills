# 项目发现与可失效缓存

## 目标

首次进入既有仓库时找到高价值事实入口；后续只做廉价失效检查和任务相关读取，避免重复递归搜索。不要把整个仓库、需求正文或架构结论复制进缓存。

Greenfield/空仓库没有“当前实现”可恢复，应按 [02_跨项目研发任务路由.md](02_跨项目研发任务路由.md) 的 Greenfield 流程工作；只有工程基线建立后，本文件的缓存才有实际价值。

## 触发时机

- 首次进入既有仓库或缓存缺失；
- 每个独立开发任务或新工作会话开始；
- `pull`、同步、切换分支、rebase、历史改写后；
- 规则、需求、Contract、Schema、Migration、Manifest、配置或测试入口可能变化时；
- 同一任务内没有仓库状态变化时复用本次结果，不为形式重复执行。

只读任务未经写入授权时，不创建或刷新磁盘缓存；执行等价的内存内有界发现。

## 发现顺序

1. 定位真实仓库根；从子目录开始时向上寻找版本控制根和规则文件；
2. 先读取 root 到目标路径适用的 `AGENTS.md`、`CONTRIBUTING` 或同等规则；同时可识别 Claude、Copilot、Cursor、Gemini、Windsurf 等规则入口，但是否生效以宿主/项目规则为准；
3. 识别根 README、需求/PRD/Spec/RFC、架构/ADR、Contract/Schema、Migration、配置、Manifest/lock、CI 和测试入口；
4. 只沿规则导航和任务关键词读取相关内容；
5. 排除 `.git`、依赖目录、构建产物、虚拟环境、缓存、符号链接和明显二进制文件；不得读取或缓存 `.env`、凭据、密钥和生产数据；
6. 对实际读到的材料记录路径、适用范围，以及它描述当前行为、目标行为还是背景信息；冲突时不静默确定权威性；
7. 有界检查模块边界、API/事件/Schema、数据 Owner、Migration 或契约测试；未发现则记录检查范围并跳过，不创建占位架构。

## 本地缓存

固定路径：

```text
.agents/project-context.json
```

它是**目标项目本地 disposable cache**，不提交 Git。目标项目应将它加入 `.gitignore`。

缓存只保存：

- 仓库相对路径；
- 事实源分类；
- 文件大小和 SHA-256；
- 文档首个标题；
- 高价值目录摘要；
- `package.json` 中实际存在的 scripts；
- 生成器版本和 Git 基线信息；
- 使用北京时间并带 `+08:00` 偏移的生成时间。

不要保存绝对路径、需求正文、源代码摘要、凭据或推断出的架构结论。

## 首次/后续运行

只有项目写入已授权且宿主有持久文件系统时才落盘：

```text
python <skill>/scripts/coding.py discover --root <repo> --json
```

结果：

- `created`：此前没有缓存；
- `refreshed`：候选事实源或 Git 可见状态使缓存失效，已重建；
- `cache_hit`：没有发现候选事实源失效信号。

`cache_hit` **不代表普通源码没有变化**，更不能替代 `git diff`、真实实现、调用链和相关测试调查。

## 必须刷新或重建

- cache schema/生成器不兼容；
- 缓存损坏；
- 关键规则、需求、Contract、Migration、Manifest 或测试入口新增/删除/移动/修改；
- Git 历史改写导致旧基线不再是当前提交祖先；
- 缓存来自另一仓库或路径逃逸；
- 用户明确要求完整刷新。

刷新失败时保留原错误并重新做受限发现，不静默使用已知过期缓存。

## 正确用途

缓存回答“事实源在哪里”，不回答“当前实现一定怎样”。执行任务时至少重新读取：

- 本次适用规则和需求；
- 实际入口和调用链；
- 数据流、接口或配置；
- 相关测试和错误处理；
- 当前 Git diff 与工作区状态。

如果缓存与仓库冲突，以当前仓库内容为准并刷新缓存。

## 无脚本/无持久文件系统

使用宿主自带文件搜索按同一分类做受限发现。不要创建平台专属第二缓存格式。无法持久化时明确后续新会话可能重新发现；不要承诺“以后不再扫描”。
