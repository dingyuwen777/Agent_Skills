# 系统级分析与代码整洁收口

## 系统级分析与能力归一

系统级分析先于局部实现，但不等于全仓扫描，**系统级分析不等于扩大修改范围**。围绕当前任务沿真实能力链闭合：

```text
入口 / 消费者
→ 调用链、数据流、状态流
→ 能力 Owner / Contract
→ 状态与副作用
→ 现有实现 / tests / docs / ops
→ 方案与验证
```

- 先查同类生产入口和现有实现，区分可复用能力、真实重复，以及因生命周期、安全、事务、版本等边界必须独立的实现。
- 真正隔离时局部修复；已有能力满足语义时**复用现有正确实现**；稳定真实重复时抽**公共实现**；同一能力被多处维护规则、状态或事实时，优先收敛**单一事实源**和明确**能力 Owner**，形成 `Owner → Contract/入口 → 实现/状态 → consumers → tests/docs/ops` 的**统一能力治理链**。
- **不要为抽象而抽象**：只有代码相似但语义、生命周期、失败、安全或事务边界不同，不强行共用。
- 局部补丁若绕过 Owner、制造第三套实现、第二份状态或第二套规则，重新检查复用或能力归一。
- 系统性方案说明复用项、必须保留的差异、公共/统一 Owner、兼容/Migration 和验证闭环。
- 恢复能力链的目的只是确认当前改动应该落在哪里、哪些边界必须保持；没有新的 Requirement、阻塞或直接风险时，不因为看到了相邻问题就扩大当前 Scope。

## 受影响代码域整洁收口

持久实现完成时，对**本次修改直接新增、修改或因此确认失效**的文件/模块责任做整洁审计，使本次受影响代码域**整体清晰、易读、可维护**，并清理本次变化直接产生的**垃圾残留**。

- 清理**因本次变化**确认无用的死代码、废弃分支、重复 helper/wrapper、未使用 import/变量、debug/TODO 和其他直接残留。
- **本次修改之前已经存在**的相邻死代码、TODO、重复实现、命名或结构技术债，默认只记录 Finding，**不自动纳入当前 Scope**；只有它真实阻塞当前目标、正确性、验证，或用户明确要求时才加入，并重新评估风险和验证范围。
- 删除前不能只看“零引用”；检查 public API/外部 consumer、配置/DI、**反射/动态加载**、**插件注册**、生成代码/脚本、**Migration/回滚**、deprecated/兼容路径等隐式入口。
- **无法确认安全时不删除**，记录未验证项或拆成后续任务。
- **不把代码清理扩大成无关重构**，不覆盖用户工作；历史大清理另立任务。
- 收尾时检查**本次 Agent 创建**且任务之后不再需要的**临时 / scratch / debug** 文件、目录、下载物、探针输出和一次性生成物并删除；**不得删除预存在或用户所有**的文件，也不得仅凭名称像临时文件就清理。仍是验证输入、交付物、审计证据或用户要求保留的产物继续保留。
- 仅删除上述无后续用途的任务临时产物，且没有改变交付代码、Contract、配置或运行输入时，**不使既有 Green Evidence 失效**，不机械重复测试；如果清理本身改变了实际交付状态，只重跑受影响边界的验证。
- 清理后只重读当前直接受影响文件，并按 [07_通用验证与证据策略.md](07_通用验证与证据策略.md) / L1 Fast Path 运行与清理风险匹配的目标测试或相关回归；不因为“做了整洁收口”机械扩大成全仓验证。
