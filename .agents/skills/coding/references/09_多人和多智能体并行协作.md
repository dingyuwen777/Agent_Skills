# 多人和多 Agent 并行协作

## 支持范围与冲突

本 Reference 是多 Agent 唯一 **Orchestration Contract**；Router 不创建/调度 Agent，本文件也不复制 Coding / Testing / Review / Research / Figma 专业方法。只治理真实已有的责任、依赖、冲突、Delegation、并发、Handoff 与集成。

多人/多变更先同步**已授权同步**状态，确认 Change/等价施工单元的 Owner、分支、影响路径、Contract/Schema/数据、依赖和验证环境；使用 `coding-change/v1` 时可运行 `python <skill>/scripts/coding.py conflicts --root <repo> --json`，退出码 2 表示显式重叠。同步/rebase/共享事实变化后重查，旧“无冲突”不覆盖新状态。

- 独立边界可并行；有 blocker 按 DAG 顺序，frontier 才并行。
- Contract/Schema/Migration/共享数据先冻结统一语义，再让消费者并行；不静默解决冲突。
- 默认 Vertical Slice；Wide Refactor 用 `expand → migrate batches → contract`。
- 共享 checkout/state 服从下面的 Single Writer Lease；不要制造 merge conflict 再把协调成本算成收益。

## 多 Agent Value Gate

只拆有真实独立价值：`NO_SPLIT`=成本≥收益；`MAY_SPLIT`=收益不确定；`MUST_SPLIT`=存在可独立验收单元，且并行、上下文隔离或独立复核收益明确。用户要求多 Agent 也不能跳过 Value Gate。宿主支持时 `MUST_SPLIT` 真实委派；无 delegation/禁用/无 Provider 时说明并**降级为单 Agent**，不阻塞、不冒充，也不绕过项目硬门禁。

只启用最少角色：`Explorer`/`Researcher` 只读事实，`Worker` 限定写，`Tester` 默认只读验证，`Reviewer` 只读审查；Role 只定目标/范围/权限/输出，专业方法仍归对应 Skill。

### Depth / Budget / Writer Guard

Agent_Skills delegation 默认 **root-only**：Main/Parent 发起，**child 默认不得**再 delegate。默认 `active child budget = 3`；这是协调预算，不覆盖宿主更低硬上限。只有 Parent 能基于额外独立 frontier、隔离和明显收益显式授权更多/更深 delegation，宿主不支持就不模拟。

**Single Writer Lease**：同一 checkout/shared mutable state 默认同时一个 write-capable Worker；只有 worktree/environment、路径、Contract/Schema、共享状态和验证环境都隔离时才发放多个 writer lease。

## Delegation / Handoff Contract

每个 child 至少拿到：**子任务目标**、`base_revision`、`decision_epoch`、Requirement/Contract/已确认决定、**允许读取范围**、**允许写入范围**、**依赖**、**预期输出**、**必须返回的 Evidence**、**父 Agent 集成验证**。授权只能收窄，父 Agent 的 Git/merge/Release 权限不自动下放；不要用整段会话代替契约。

`decision_epoch` 是 task/session 内的单调决策版本；Requirement、Contract、Schema、Scope、Authorization 或 Acceptance 出现实质变化时递增，不落盘。

Handoff 用轻量固定标题，**不强制统一 JSON**：

```text
STATUS
SCOPE
REVISION
SUMMARY
EVIDENCE
CHANGES
VALIDATION
RISKS
PARENT_DECISION
```

`REVISION` 回报实际观察到的 revision/epoch；未知就写 unknown，不能猜。

### Parent 集成与 Freshness

Parent 不把 child“完成”文本当 Evidence；必须检查真实 diff/产物、需求符合性、任务重叠、相关验证，再更新 Change。child 的 observed revision/epoch 与当前相关事实不一致时标记 `STALE_RESULT`，重读受影响事实并重新验证后才可复用/重跑/丢弃；旧结果不能直接驱动写入、Review 或完成。

### Failure / Conflict / Lifecycle

- 同一 delegation 只对明确 transient 失败自动重试，默认最多 **1 次**；再次同类失败 `STOP_CHILD_RETRY` → Parent fallback/replan。权限、Contract、确定性测试失败不机械重试。
- **Evidence Conflict Gate**：Agent 结论冲突时**禁止投票**；按 current revision、source owner、正式 Contract、可复现 test/probe 和更直接 Evidence 裁决，不足则保持 `UNKNOWN`。
- **Join / Cancel Guard**：Evidence 已充分或 child stale/obsolete 时停止等待；宿主支持时 interrupt/cancel。交付前 required child 不得处于未知 running，write-capable child 不得仍有活动写入。
- Parent 在 task/session 内维护最小 **Orchestration Ledger**：split decision、`decision_epoch`、active children、writer lease、repair round、blocking findings、follow-ups；**不落盘、不入 Git、不新增服务**。

### Repair Loop Owner

Main/Parent 是 **Repair Loop Owner / Finding Admission Gate**；Reviewer 不直接派 Worker。只把接纳的 `IN_SCOPE_BLOCKING` 以**最少充分** Finding/Evidence/scope/验收重新委派，不转发**完整对话历史**；继续/停止/replan 服从 Review Convergence Guard。

### Multi-Agent Visibility Contract

明显 `NO_SPLIT` 小任务不需要单独编排 banner；MAY/MUST、实际拆分或 fallback 时说明 Agent 数量、Role/Scope、读写和并行关系。运行中只报关键变化，结束汇总真实 Agent/Evidence；没启动就不能声称启动。

### Host Adapter Contract

先探测真实 capability：Codex / Claude Code / Cursor 使用可用原生 delegation；Cursor 多 Writer 优先隔离 worktree/environment；DeepSeek Harness 检查 `ctx.subagents` / provider registry。Adapter 只负责委派，不自动装 Provider、不固定模型、不扩大授权。

DSH 的 `maxDepth` / `toolFilter` 只能缩小递归和直接 mutation surface；`toolFilter` **不是 permission lattice / sandbox**，不得宣称与宿主级 readonly enforcement 等价，真实权限仍服从 DSH permission/sandbox 与 Parent 授权。

## Effectiveness Feedback 与停止条件

补完安全/收敛 Guard 后，不继续凭感觉增加 Agent、角色或规则。调整 NO/MAY/MUST、active budget 或返修阈值时，优先用真实历史任务比较 wall-clock、Agent 数、repair rounds、CI rerun、人工干预及宿主可得的 token/tool calls；不自动上传 telemetry。

多人/高风险并行只有在用户和仓库规则授权时才创建分支/worktree，创建后先检查基线。Git 可见 Change 不能锁住其他 clone，也看不到未推送工作；信息不足只能报告“基于当前可见状态”。
