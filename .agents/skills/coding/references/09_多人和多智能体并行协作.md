# 多人和多 Agent 并行协作

本 Reference 是多 Agent 唯一 **Orchestration Contract**；Router 不创建/调度 Agent，各专业方法仍归对应 Skill。

## 冲突与并行

多人/多变更先同步已授权状态，确认 Change/等价单元的 Owner、分支、路径、Contract/Schema/数据、依赖和验证环境；`coding-change/v1` 可运行 `python <skill>/scripts/coding.py conflicts --root <repo> --json`，exit 2 表示重叠。共享事实变化后重查。

独立边界才并行；blocker 按 DAG，frontier 才并行。Contract/Schema/Migration/共享数据先冻结统一语义。默认 Vertical Slice；Wide Refactor 用 `expand → migrate batches → contract`。

## Delegation Value / Independence Requirement 与角色

多 Agent 决策固定分成两个正交维度：

```text
Delegation Value = NO_SPLIT | MAY_SPLIT | MUST_SPLIT
Independence Requirement = OPTIONAL | REQUIRED
```

### Delegation Value

- `NO_SPLIT`：delegation 成本≥收益，保持单 Agent；
- `MAY_SPLIT`：存在独立候选，但并行/隔离收益不确定；
- `MUST_SPLIT`：存在可独立验收单元，且并行、上下文隔离或专业分工收益明确。

用户要求多 Agent 也**不能跳过独立价值判定**。宿主支持时 `MUST_SPLIT` 真实委派；无 delegation/禁用/无 Provider 时说明并降级单 Agent继续可安全完成的工作，不伪称已拆，也不把“缺少并行能力”误写成整个任务不可做。

### Independence Requirement

- `OPTIONAL`：当前完成结论不依赖独立身份，Parent 自检与常规验证足够。
- `REQUIRED`：项目/风险/Review/Testing/交付门禁要求结果必须由独立 Reviewer、Tester 或等价独立验证取得。

**Independence Requirement 与 Delegation Value 互不替代。** `NO_SPLIT + REQUIRED` 完全合法：实现可以单 Agent，但最终结论仍必须经过独立复核；`MUST_SPLIT + OPTIONAL` 也合法：可以为了效率拆分，但不制造不存在的独立 Review 门禁。

无 delegation 时对 `MUST_SPLIT` 的 fallback **不能因此降级 `REQUIRED` independence**。若当前宿主没有满足 required independence 的能力，则实现/调查中无依赖部分继续，依赖独立性的 Review、merge/release/delivery 结论保持 blocked/incomplete。

只启用最少角色：`Explorer/Researcher` 只读事实，`Worker` 限定写，`Tester` 默认只读验证，`Reviewer` 只读审查。

### Depth / Budget / Writer Guard

默认 **root-only**：Main/Parent 发起，**child 默认不得**再 delegate；`active child budget = 3`，并服从宿主更低硬上限。只有 Parent 能在额外独立 frontier、隔离和收益有 Evidence 时授权更多/更深 delegation。

**Single Writer Lease**：同一 checkout/shared mutable state 默认一个 write-capable Worker；多 Writer 必须同时隔离 worktree/environment、路径、Contract/Schema、共享状态和验证环境。

## Delegation Contract / Handoff

不创建 Planner，不维护任务队列；编排由主 Agent/Parent 持有。每个 child 至少取得：**子任务目标**、**输入事实**（`base_revision`、`decision_epoch`、Requirement/Contract/已确认决定）、**允许读取范围**、**允许写入范围**、**依赖**、**预期输出**、**必须返回的 Evidence**、**父 Agent 集成验证**。授权只能收窄，Git/merge/Release 权限不自动下放，不用完整会话代替契约。

`decision_epoch` 是 task/session 内单调决策版本；Requirement/Contract/Schema/Scope/Authorization/Acceptance 的实质变化才递增，不落盘。

Handoff 用轻量标题，**不强制统一 JSON**：

```text
STATUS
SCOPE
REVISION
SUMMARY
EVIDENCE
CHANGES
VALIDATION
RISKS
PARENT_DECISION
```

REVISION 报实际 observed revision/epoch，未知写 unknown。

## Parent Guards

子 Agent 返回后，主 Agent 必须**检查实际 diff 和工作区**、复核需求/重叠，并**运行目标及整体相关验证**；只以真实 Evidence 更新状态。

- **Freshness**：observed revision/epoch 与当前相关事实不一致即 `STALE_RESULT`；重读并重验证后才复用/重跑/丢弃，不能直接驱动写入、Review 或完成。
- **Failure**：同一 delegation 仅对明确 transient 自动重试，默认最多 1 次；再次同类失败 `STOP_CHILD_RETRY` → fallback/replan；权限/Contract/确定性失败不机械重试。
- **Evidence Conflict Gate**：结论冲突时**禁止投票**；按 current revision、source owner、Contract、可复现 test/probe 和更直接 Evidence 裁决，不足保持 `UNKNOWN`。
- **Join / Cancel Guard**：Evidence 已充分或 child stale/obsolete 时停止等待；宿主支持则 interrupt/cancel。交付前 required child 不得未知 running，write child 不得仍活动。
- **Orchestration Ledger**：Parent 仅在 task/session 跟踪 split decision、`decision_epoch`、active children、writer lease、repair round、blocking findings、follow-ups；**不落盘、不入 Git、不新增服务**。

### Repair Scheduling Owner

**Reviewer owns Finding classification；Parent owns scheduling。** Reviewer 独立判断 Finding 的 Evidence、severity、Scope、Delivery Effect 与 Action；Reviewer 不直接派 Worker。Main/Parent 只负责 repair scheduling、Worker 选择、retry/fallback、repair round 和最少充分 Handoff。

Parent 只对 `Scope=IN_SCOPE + Delivery Effect=BLOCKING + Action=AUTO_REPAIR` 且已有修改授权的 Finding 创建当前返修委派；Handoff 只携带必要 Finding/Evidence/scope/Acceptance，不转发**完整对话历史**。

Parent **不能降级** Reviewer 已确认的 BLOCKING、不能把 OUT_OF_SCOPE 改成 IN_SCOPE、不能自行关闭 Finding。分类变化只能由新直接 Evidence 触发 Reviewer reclassification、正式 Requirement/Acceptance 变化后的 Reviewer re-review，或 Reviewer 撤回。继续/停止/replan 服从 Review 的 Net Delivery Convergence；`FOLLOW_UP_CANDIDATE` 走持久化授权门禁，不进入当前 repair scheduling。

### Multi-Agent Visibility Contract

明显 NO_SPLIT 小任务不刷单独 banner；MAY/MUST、实际拆分或 fallback 才说明 Agent 数量、Role/Scope、读写和并行关系。运行中只报关键变化，结束汇总真实 Agent/Evidence。

### Host Adapter Contract

Codex / Claude Code / Cursor 使用真实原生 delegation；Cursor 多 Writer 优先隔离 worktree/environment；DeepSeek Harness 检查 `ctx.subagents`/provider registry。Adapter 不自动装 Provider、不固定模型、不扩大授权。DSH 的 `maxDepth/toolFilter` 只缩小递归/直接 mutation surface；`toolFilter` **不是 permission lattice / sandbox**，真实权限仍服从 DSH permission/sandbox 与 Parent 授权。

## Effectiveness Feedback

补完 Guard 后不继续凭感觉增加 Agent/角色/规则。调整 Value Gate、active budget 或返修阈值时，用真实历史任务比较 wall-clock、Agent 数、repair rounds、CI rerun、人工干预及宿主可得 token/tool calls；不自动上传 telemetry。Git 可见 Change 不能锁其他 clone/未推送工作，信息不足只报告“基于当前可见状态”。
