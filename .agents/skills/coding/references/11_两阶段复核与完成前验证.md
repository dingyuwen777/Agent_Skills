# 两阶段复核与完成前验证

## 1. 第一阶段：需求符合性

### Review A1：上游要求 → 当前变更

重新读取用户已确认决定、正式 Roadmap/Spec/Feature/Release 完成定义和适用项目规则，不把当前变更成功标准当需求全集。检查：

- 上游适用要求是否全部进入当前变更；
- 是否有 requirement omission；
- `explicitly_deferred` 是否有批准依据；
- `not_applicable` 是否有事实依据；
- 是否错误使用当前 Change、历史聊天或测试结果作为上游需求来源；
- 用户没有再次提醒的已固化要求是否仍被主动纳入。

测试通过、CI 全绿、当前 checklist 全勾都不能替代 A1。

### Review A2：当前变更 → 实现 / 测试 / 文档

确认：

- 目标行为真实存在；
- 范围完成、非目标未偷偷实现；
- public API/ABI/CLI、数据、配置、格式和合法行为保持约定兼容；
- 用户确认的关键决策被执行；
- `satisfied` 有实现和当前验证证据；
- Validation Matrix 每个 `required` 有匹配证据；
- `not_applicable` 不是为了少跑测试；
- Mock/Fake 没冒充真实 persistence/runtime/device/remote；
- Golden Path 没被用来冒充全部状态；
- Build/Package/Runtime 没因局部测试绿色被遗漏；
- External Probe 只有必要时有界执行；
- 代码、测试、正式文档和变更契约一致。

## 2. Completion Audit 与反向审计

使用 Completion Gate 时复核：

```text
upstream_re_read
change_coverage
reverse_audit
unresolved_cleared
```

反向审计按真实边界选择，不机械套前后端模型。CLI、Library、Schema、Data、Mobile、Embedded、Package、IaC 都应按各自公开入口 → runtime/consumer → 最终结果反向检查。

## 3. 第二阶段：代码质量

检查：

- 正确性和边界条件；
- 错误处理和异常传播；
- 安全、隐私、输入边界；
- 兼容、Migration、部署和回滚；
- 并发、性能和资源生命周期；
- 测试是否验证真实行为；
- 测试层级与声称证据是否一致；
- public API/ABI/CLI/serialization/file format 和 consumer compatibility；
- 命名、注释和维护成本；
- 所有新增/修改 public/exported/internal/private/helper 函数是否都有函数级中文说明；复杂逻辑是否解释关键 `why/invariant/risk/compatibility`；
- Agent 自有时间是否使用 `Asia/Shanghai`，外部协议其他时区是否保持原始语义并在展示边界正确转换；
- 仓库已有 logging/event/telemetry 时，关键生命周期/异步/外部 I/O/Retry/部分失败/终态是否有最小充分可观测性；
- 人类可读日志是否使用 `[YYYY-MM-DD HH:mm:ss.SSS source.ext L<line>] [LEVEL] message`；结构化外部 Contract 是否提供等价字段；
- 观测是否脱敏且不泄露 Secret/Token/密码/敏感 Raw/PII；
- 无关改动、重复实现和失效内容；
- 用户未提交修改是否保留；
- 方案是否由目标/约束/根因推导，是否存在无证据复杂度；
- Runtime/包管理器/build/依赖是否保持项目锁定事实，没有被普通任务静默升级/替换。

严重/重要问题必须先解决，不用“后续优化”掩盖当前缺陷。

## 4. Ready Check

只对 Coding Change carrier 使用：

```bash
python .agents/skills/coding/scripts/ready_check.py --root . --require-active-ready
```

必要时 `--change-root`；PR 可用 `--changed-since`。

它不能判断自然语言需求是否漏项、Evidence 语义是否充分或 Validation Matrix 是否选对层，因此不能替代 A1/A2。

## 5. 新鲜证据门禁

每个结论先回答“什么命令/检查能证明”，然后本轮：

1. 运行完整命令；
2. 读取完整输出；
3. 检查退出码、失败数、警告和跳过项；
4. 对照原始症状、上游完成定义、成功标准、Validation Matrix 和影响范围；
5. 只陈述证据直接支持的状态。

| 结论 | 必需证据 | 不足以证明 |
| --- | --- | --- |
| 行为测试通过 | 当前目标测试退出码 0、失败数 0，并断言目标行为 | 旧日志、Mock 调用次数、代码看起来对 |
| Public Contract 兼容 | 当前 schema/API/ABI/CLI/格式/consumer 检查 | 手写 Mock 字段、内部 Unit |
| Runtime/Persistence Integration 通过 | 当前项目真实依赖的 integration 证据 | 更弱 Fake、静态检查、语义不同的替代依赖 |
| 用户/调用者工作流通过 | 当前真实入口的 Workflow Acceptance | private helper Unit |
| 跨组件接通 | 当前关键真实组件链 Golden Path | 各组件单独 Mock/Unit |
| 外部依赖当前可用 | 当前有界 Probe + 环境/费用/权限/数据范围 | 历史 Fixture/Raw/Mock |
| Build/Package/Startup 成功 | 当前正式 build/package/install/startup 退出码 0 + artifact 核对 | Lint/源码 Unit |
| Bug 修复 | 原始症状消失 + 正确 Red/Green 回归 | 只改代码或只跑修复后测试 |
| 正式单元完成 | Requirement Traceability + Matrix + Completion Audit + 实现证据 | CI 全绿 |
| 子 Agent 完成 | 主 Agent 看 diff 并重新验证 | 子 Agent 成功报告 |
| 可发布 | 完整交付门禁 + 正式 artifact/runtime + 部署/回滚状态 | 本地目标测试 |

命令不能运行时保留原错误，说明未验证内容、原因和风险。禁止删/跳/篡改失败测试、吞异常或降低门禁。

## 6. 依赖与网络事实

涉及版本、API、标准、依赖、镜像或外部服务且信息可能变化时，优先官方一手资料。普通功能不顺手升级。中国大陆/海外网络下载源选择按 [03](03_编程语言与工具链适配规则.md) 的执行环境规则。

## 7. Git Review

提交/PR/合并前检查：

- 当前 branch/HEAD；
- 工作区和未提交修改；
- diff 仅包含当前任务；
- commit message 使用中文；
- 没有 force push/history rewrite/破坏性清理；
- CI/Branch Protection/Ruleset 没被绕过；
- 合并、发布、部署有明确授权；
- 合并后重新确认 main/目标分支和必要最终验证。

## 8. 完成交付

至少报告：变更摘要、逐文件目的、项目形态/阶段/工具链/风险、Requirement Traceability、Validation Matrix、Completion Audit、Contract/Schema/Migration、文档同步、实际验证命令和退出码、未验证风险、兼容/依赖/部署/回滚、Git/PR/CI/合并状态。
