# 审查执行流程

## 0. Review Phase State Machine

`FIRST_ASSEMBLY → REPAIR_VERIFY → ESCAPE_CORRECTION → REVIEWER_RECOVERY → FINAL`，同一 frozen Target 单调推进。

- `FIRST_ASSEMBLY`：Root Invariant / Material Projection closure + single synthesis。
- `REPAIR_VERIFY`：只核**原 blocking findings / 本轮新 diff**（`reviewed_head → repair_head` **repair diff**）/ **直接相邻**回归 / **Acceptance Criteria**。
- `ESCAPE_CORRECTION`：**未改变的旧基线**出现 `FIRST_REVIEW_ESCAPE` 时**不得立即发布单条**；只允许一次 **fresh blind Review Assembly** → 剩余 material projections closure → **consolidated review-correction batch**；`escape budget=1`，**不得递归**。
- `REVIEWER_RECOVERY`：budget 用尽仍漏旧基线 → `REVIEW_PROCESS_FAILURE`（**内部恢复状态、非终态**）：说明**遗漏原因**，只重开受影响 Root Invariant，关**剩余 material projections**、合并 draft、**single synthesis**；**不得作为用户/作者终态**。
- `FINAL`：只返回 `NO_FINDINGS_WITHIN_SCOPE / NON_BLOCKING_FINDINGS / CHANGES_REQUIRED / BLOCKED / UPSTREAM_DECISION_REQUIRED / CAPABILITY_BLOCKER` 或项目等价状态；真实 blocker 不得为结束流程被忽略。

**Baseline Closure Freeze**：首轮/纠偏 closure 后绑定 `reviewed_head + Requirement revision + Root Invariant / Material Projection Matrix`；未改旧基线关闭，仅 `REPAIR_DIFF / NEW_REQUIREMENT / NEW_EXTERNAL_FACT / BASE_DRIFT` 可重开，禁止**无限范围** Full Review。

## 1. 冻结 Target 与 Coverage

恢复 Target/base/reviewed_head、模式/授权、Requirement/Acceptance/Contract、规则/tests/CI。

Coverage 状态：`covered / ruled_out / not_applicable / unknown`。docs diff 做 Reverse Documentation Audit：查 `Existing/Machine Owner / Growth / Reverse impact/exit`；需修文档则 Handoff Docs。

复合机制写 **Root Invariant / Material Projection Matrix**；状态 `confirmed / ruled_out / covered_by_evidence / not_applicable / unknown`，material unknown 先取证。**达到 Systemic 条件**时 route refresh 到 `执行模式=诊断`，复用 Coding [`22_根因调试.md`](../../coding/references/22_根因调试.md)，按 Invariant → Lifecycle/state → Failure Boundary → Projection 闭环，保持**机制内完整、任务外有界**；**新代码/Requirement/外部事实引入的不记** First-pass Coverage Miss。

### First Review Assembly Gate / No-Findings-Drip Gate

固定非递归 Assembly；blind 视角只返**内部 draft**，Parent **一次 synthesis / single synthesis**。Root Invariant、material unknown、**Omission / Coverage Audit**、Counterevidence 未闭合前**禁止发布** Finding/触发 Repair Batch/逐条 request-review，也**不得向作者发布部分 Findings**或**递归开启 Full Review**。首轮旧基线漏审 = **First-pass Coverage Miss**。

## 2. Evidence、模式与 Owner

`Requirement/Risk → Evidence → 实际边界 → 断言 → Gap`；测试名/覆盖率/CI Green 不等于充分证据；新增/系统测试 Handoff Testing。

`review-only` 只报告；`review-and-test` 由 Testing 补证据；`review-and-fix` 由 Coding 修复/Green → Testing Regression（适用）→ Repair Package Closure → `REPAIR_VERIFY`。Reviewer owns Finding classification；Parent owns repair scheduling，不得单方降级 blocker/改 Scope/关闭 Finding。

## 3. Second-pass Repair Verification

作者 Repair Batch 先通过 Coding **Repair Package Closure / Re-review Admission Gate**；第二轮默认 `REPAIR_VERIFY`，不是第二次 Full Review。

### New-Finding Provenance Gate

**正常第二轮新 Finding** 必须声明来源：
`REPAIR_DIFF | UNRESOLVED_FINDING | NEW_REQUIREMENT（新 Requirement） | NEW_EXTERNAL_FACT（新外部事实） | BASE_DRIFT`。

`UNCHANGED_BASELINE` 不能直接成为正常新 Finding：首次走 `FIRST_REVIEW_ESCAPE → ESCAPE_CORRECTION`，budget 用尽走 `REVIEWER_RECOVERY`。第二轮只验证 repair closure，不重审旧代码。Repair Package 本可捕获的 repair-diff blocker = `REPAIR_PACKAGE_ESCAPE`：对 repair diff 一次 bounded sibling closure / single synthesis 后统一返回。

## 4. Review Convergence Guard

### Net Delivery Convergence

无本轮引入的**同级或更高级** BLOCKING，且 blocker/影响下降或 Acceptance Evidence 增强才是 `Delivery Convergence`；仅根因更清楚是 `Diagnostic Progress`，两者**不等价**。正常路径是一批 Finding → 一个 Repair Package → 一次 delta re-review。

**连续两轮**无净收敛 → `STOP_REPAIR_LOOP / root-cause reanalysis`；同一 blocker **连续两次修复**仍在先 repair-plan reset；`3 个 automatic repair rounds` 是 hard ceiling，**不是自动 PASS**。

## 5. 结束条件

Requirement/Acceptance、Coverage/Material Projection、Finding Evidence 与新鲜验证处理后才结束；缺事实先有界恢复。仅真实 `OWNER_DECISION / AUTHORIZATION_REQUIRED / REQUIRED_USER_INPUT / CAPABILITY_BLOCKER` 向上游请求，不把 Reviewer 没审完当 blocker。
