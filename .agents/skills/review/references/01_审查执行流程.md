# 审查执行流程

本 Reference 只定义 Review 执行与收敛；研发规范归 Coding，测试方法归 Testing。

## 0. Review Phase State Machine

同一 frozen Review Target 单调推进：

```text
FIRST_ASSEMBLY → REPAIR_VERIFY → ESCAPE_CORRECTION → REVIEWER_RECOVERY → FINAL
```

- `FIRST_ASSEMBLY`：完成 Root Invariant、Coverage/Material Projection closure 和首轮 single synthesis。
- `REPAIR_VERIFY`：只核**原 blocking findings / 本轮新 diff**（`reviewed_head → repair_head` 的 **repair diff**）/ **直接相邻**回归 / **Acceptance Criteria**。
- `ESCAPE_CORRECTION`：从**未改变的旧基线**发现 `FIRST_REVIEW_ESCAPE` 时，**不得立即发布单条**；只允许一次 **fresh blind Review Assembly**，关闭同根剩余 material projections 后形成一个 **consolidated review-correction batch**；`escape budget=1`，**不得递归** correction。
- `REVIEWER_RECOVERY`：escape budget 用尽后仍有旧基线漏审 → 内部 `REVIEW_PROCESS_FAILURE`。它是**内部恢复状态、非终态**：说明**遗漏原因**，只重开受影响 Root Invariant，关闭**剩余 material projections**，撤销/合并冲突 draft，完成 **single synthesis**；**不得作为用户/作者终态**。
- `FINAL`：只返回 `NO_FINDINGS_WITHIN_SCOPE / NON_BLOCKING_FINDINGS / CHANGES_REQUIRED / BLOCKED / UPSTREAM_DECISION_REQUIRED / CAPABILITY_BLOCKER` 或项目等价状态。真实 blocker 不得为结束流程被忽略。

首轮或 correction closure 后形成 **Baseline Closure Freeze**：绑定 `reviewed_head + Requirement revision + 已关闭 Root Invariant / Material Projection Matrix`。未修改旧基线在当前交付内视为已关闭审查面；只有 `REPAIR_DIFF / NEW_REQUIREMENT / NEW_EXTERNAL_FACT / BASE_DRIFT` 可重开相应边界，Reviewer 自身漏审不能借机重开**无限范围** Full Review。

## 1. 冻结 Review Target

先恢复：`Review Target/base/reviewed_head`、模式/授权、Requirement/Acceptance/Contract/Schema/不变项/非目标、项目规则/Coding Context/tests/CI。先读规则与 Requirement，再读 diff/调用链；PR 描述、作者 checklist、CI Green 不是需求全集。

## 2. Review Coverage Map 与首次发布闭包

Coverage 只纳入真实适用域：Requirement、Contract/compatibility、state/lifecycle/error/recovery、并发/幂等/事务、安全/权限、用户行为、test/evidence、build/runtime/docs；状态 `covered / ruled_out / not_applicable / unknown`。docs diff 做 targeted Reverse Documentation Audit：查 `Existing/Machine Owner / Growth / Reverse impact/exit`；需要修文档时 Handoff Docs。

复合机制建立 **Material Projection Matrix**：先写 **Root Invariant**，再枚举会改变 Review terminal、修法、Acceptance 或 compatibility 的 sibling projections；状态 `confirmed / ruled_out / covered_by_evidence / not_applicable / unknown`。material unknown 发布前必须有界取证；非 material unknown 可记录剩余风险。Systemic 时 route refresh 到 `执行模式=诊断`，复用 Coding [`22_根因调试.md`](../../coding/references/22_根因调试.md)，按 Invariant → Lifecycle/state/ownership → Failure Boundary → Projection 闭环，保持**机制内完整、任务外有界**；**新代码/Requirement/外部事实引入的不记** First-pass Coverage Miss。

### First Review Assembly Gate / No-Findings-Drip Gate

固定、非递归 Assembly；blind 视角互不看 Finding，只返回**内部 draft**，Parent **一次 synthesis / single synthesis**。对外发布前必须完成 Root Invariant、Material Projection Matrix 的 material unknown closure、**Omission / Coverage Audit**、Counterevidence。通过前**禁止发布** Finding/触发 Repair Batch/逐条 request-review，也**不得向作者发布部分 Findings**或**递归开启 Full Review**。首轮漏掉旧基线可推导 blocker = **First-pass Coverage Miss**。

## 3. Evidence、模式与 Owner

先做 `Requirement/Risk → Evidence → 实际边界 → 断言结果 → Gap`；测试名/覆盖率/CI Green 不是充分证据。需要新增/系统测试时 Handoff Testing。

- `review-only`：只报告；`review-and-test`：Testing 补证据；`review-and-fix`：Coding 修复/Green → Testing Regression（适用）→ Repair Package Closure → `REPAIR_VERIFY`。
- Reviewer owns Finding classification；Parent owns repair scheduling。Parent 不得单方降级 blocker、改 Scope 或关闭 Finding。

## 4. Second-pass Repair Verification

作者统一 Repair Batch 必须先通过 Coding 的 **Repair Package Closure / Re-review Admission Gate**；外部第二轮默认是 `REPAIR_VERIFY`，不是第二次 Full Review。

### New-Finding Provenance Gate

第二轮任何新增 blocker 必须声明来源：

```text
REPAIR_DIFF | UNRESOLVED_FINDING | NEW_REQUIREMENT | NEW_EXTERNAL_FACT | BASE_DRIFT
```

只有这些来源可成为正常第二轮新 Finding。若来源是 `UNCHANGED_BASELINE`，**不能**作为正常新 Finding 直接交作者：首个旧基线逃逸走 `FIRST_REVIEW_ESCAPE → ESCAPE_CORRECTION`；escape budget 已用尽则走内部 `REVIEWER_RECOVERY`。这保证第二轮职责是验证 repair closure，而不是重新找一遍旧代码问题。

本可由 Repair Package Closure 捕获的 repair-diff blocker = `REPAIR_PACKAGE_ESCAPE`：只对当前 repair diff 做一次 bounded sibling closure / single synthesis，再统一返回，不逐条滴漏。

## 5. Review Convergence Guard

### Net Delivery Convergence

无本轮引入的**同级或更高级** BLOCKING，且 blocker/影响下降或 Acceptance Evidence 增强才是 `Delivery Convergence`；只把根因说清楚是 `Diagnostic Progress`，二者**不等价**。正常路径是一批 Finding → 一个 Repair Package → 一次 delta re-review。

**连续两轮**无净收敛 → `STOP_REPAIR_LOOP / root-cause reanalysis`；同一 blocker **连续两次修复**仍在先 repair-plan reset。`3 个 automatic repair rounds` 是 hard ceiling，**不是自动 PASS**。

## 6. 结束条件

Requirement/Acceptance、Coverage/Material Projection、关键调用链、测试充分性、Finding Evidence、新鲜验证和未验证边界都处理后才能结束。缺事实/测试先由 Agent 有界恢复；只有真实 `OWNER_DECISION / AUTHORIZATION_REQUIRED / REQUIRED_USER_INPUT / CAPABILITY_BLOCKER` 才向上游请求，不把 Reviewer 自己没审完当 blocker。
