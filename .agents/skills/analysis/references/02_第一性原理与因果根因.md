# 第一性原理与因果根因

## 第一性原理不是从零发明

把问题还原到不可省略的事实、约束和机制：目标是什么 → 哪些约束不可违反 → 哪些变量真正决定结果 → 当前系统为什么产生现象 → 哪些做法只是历史习惯/类比 → 哪些改变真正切断问题机制。成熟经验仍可使用，但应能解释它解决了哪个真实机制。

分析深度由不确定性、因果复杂度、独立失败边界和复发风险决定，不由“希望最终少改一点”决定。可以经过较深分析后只需要一个很小的修复，也可能经过充分分析后确认必须改多个边界。

## 因果判断

区分相关、机制、因果、共同原因和反向因果。重要因果结论至少检查替代解释、时间顺序、适用范围和**反事实**：假设原因不存在，结果是否仍可能发生？

不要把“修改 A 后现象暂时消失”自动解释为“A 是完整根因”。还要检查修改是否真正切断了所主张的机制，以及其他已确认因素是否仍能造成同一现象。

## 根因深度门槛

目标不是每个问题都做重型 RCA，而是在进入永久方案前取得**足以改变决策的因果闭环**。

### Lightweight 闭合

局部、稳定、单因果问题满足以下条件时，可以快速闭合：

- 已确认因素能够解释全部当前症状；
- 没有未解释的独立失败边界或与结论冲突的事实；
- 没有“修过仍复发”、并发/异步、性能、partial failure、数据完整性、状态不同步等复合信号；
- 拟议修复直接切断已确认机制，而不只是遮住表面症状；
- 有最便宜且直接的验证可以证明目标行为恢复。

此时不要求大型假设矩阵、无边界调查或理想架构设计。

### 必须继续调查

出现以下任一情况，且它会改变方案选择、完成判定或复发风险时，不得过早进入“永久解决方案”：

- 根因尚未确认，当前只有相关性、猜测或单次现象；
- 同一问题反复出现，或已有修复后仍复发；
- 一个已确认因素只能解释部分症状；
- 存在多个独立 failure boundary、多个候选原因或相互放大因素；
- 当前措施只是 timeout 增大、重试、扩容、回滚、绕过、降级等症状级缓解；
- 当前证据与所主张根因存在矛盾；
- 正确性、数据、安全、并发、异步、性能或恢复语义可能改变真正修法。

继续调查只沿当前真实因果链和最有解释力的未知项扩展；新证据不能改变结论、方案或重大风险时停止，不为了“彻底”而机械扫描全部可能性。

## 根因分析

根因不是最底层组件，而是**在当前控制范围内，改变后能稳定消除或显著降低复发概率的原因**。按：

```text
症状
→ 稳定事实 / 正常参照
→ 最近变化与真实边界
→ 多个可证伪假设
→ 最小实验
→ 因果机制
→ 根因 / 贡献因素状态
→ 修复
→ symptom + mechanism + recurrence 验证
```

推进。

如果根因尚未确认但必须先行动，输出应明确区分：

- 已确认事实；
- 已确认因素；
- 候选根因；
- 当前最可能解释；
- 下一步可证伪验证。

不能把推测写成已确认根因，也不能把基于未确认根因的永久修复写成确定方案。

## 止血 / 缓解 与永久修复

紧急情况下可以先采取回滚、限流、降级、隔离、临时扩容、关闭异常入口等**止血 / 缓解**措施，目标是降低当前损失或恢复服务。

但：

```text
止血 / 缓解
≠ 根因已确认
≠ 永久修复
≠ 问题已经根治
```

只有当方案针对已确认根因或足够明确的关键机制，并取得与风险相称的完成验证后，才可以称为**永久修复**。如果止血后症状消失但致因机制仍可能存在，只能报告“当前已缓解”。

## 根因完成验证

要宣称问题已经解决，验证至少覆盖与当前问题相称的三层：

1. **症状**：原始可观察问题已经消失或达到明确成功标准；
2. **关键机制 / 原因**：导致问题的已确认关键因果链已经被切断或受控，而不是只把错误隐藏；
3. **主要复发路径**：当前证据支持的主要复发条件、独立失败边界或高风险相邻路径已经由回归、反事实、正常参照或其他直接 Evidence 覆盖。

简单问题这三层可以由同一个轻量回归同时证明；复杂问题才按真实失败边界扩展。没有证据证明的路径不声称已覆盖。
