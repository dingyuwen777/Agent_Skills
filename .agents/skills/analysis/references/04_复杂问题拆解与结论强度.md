# 复杂问题拆解与结论强度

## 按决策依赖拆

先明确最终需要回答的问题或决策目标，**不预设答案**；再向前追必须确认的事实、机制与判断。只有真正影响上层结论的项才进入拆解。没有依赖可并行，存在 blocker 按依赖顺序处理。

## 控制分析深度

每深入一层都问：新信息会改变结论、推荐、风险或边界吗？能否合理成本取得？都不会就停止。

## 独立失效模式审计

当用户要求“还有什么可优化”“全面系统排查”“是否已经最好/没有问题”时，先把当前实现、AC、测试和既有规则当作**输入证据**，而不是答案。独立从用户真实目标检查：

- **负空间**：哪些重要前提、生命周期、权限、状态、并发、失败恢复、成本或上下文边界根本没被当前完成定义覆盖；
- **反例 / 反证**：构造能让现有结论失败的真实场景，优先验证最可能改变决定的反例；
- **递归与二阶效应**：当前自动动作会不会继续制造新任务、状态、依赖、Agent、Issue、重试或副作用；
- **跨环境差异**：模型、宿主、版本、权限和真实运行环境变化后，当前保证是否仍成立；
- **门禁盲区**：当前测试/Review/CI 能证明什么，以及什么即使全绿仍未被证明。

不得用“当前实现就是这样”“现有规则已经覆盖”“测试都绿”或自己刚形成的方案**循环证明**不存在其他高价值问题。只有完成上述独立审计后，才能在明确的**已审计范围**内表述“没有发现更多高价值缺口”；仍存在的**未验证**边界必须列明。

“全面”不等于无限枚举理论风险。已经覆盖主要失败路径、剩余未知不会改变当前决定时，仍按证据充分原则停止。

## 结论强度

确认 = 直接事实或高质量一致证据；高度支持 = 多条独立证据且主要替代解释已排除；倾向 = 方向一致但有重要未验证条件；可能 = 有合理机制但证据不足；未知 = 无法可靠判断。没有统计依据不随意给概率。

## 输出未确定性

只报告会影响行动的未确定性：缺什么、为什么重要、如何验证、验证前采用什么安全默认。
