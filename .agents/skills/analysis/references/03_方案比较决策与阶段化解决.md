# 方案比较、决策与阶段化解决

## 1. 从真实约束生成方案

方案必须从当前目标、现状、资源和限制推出，而不是从“行业最佳实践”反推用户应该建设什么。

优先顺序：

```text
复用已有能力
→ 最小修改解决当前问题
→ 必要的结构性调整
→ 只有明确触发条件出现后才增加长期能力
```

## 2. 默认给一个推荐

用户问“怎么做”时，优先给推荐方案、为什么适合当前情况、最重要的代价/风险，以及怎么验证它真的解决问题。只有存在真实不同取舍时才给少量备选。

## 3. 当下方案与理想方案

### 当下方案
当前条件就能实施；系统解决眼前问题而非掩盖；控制范围和副作用；有明确验证；不主动制造未来迁移死路。

### 理想方案
解决更大规模或长期约束；明确什么时候才值得做；说明与当下方案的演进路径；不把未来可能性变成当前必做清单。

## 4. 比较维度

只比较会改变决策的维度：是否解决目标、复杂度/成本、风险/可逆性、对现有系统影响、依赖/迁移成本、证据/可验证性、长期维护成本。不要为了表格完整制造无意义评分。

## 5. 决策输出

证据足够时明确给推荐；关键取舍依赖用户价值选择时，给出决策边界和各自后果，不假装存在唯一客观答案。
