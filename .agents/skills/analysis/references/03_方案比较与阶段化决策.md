# 方案比较与阶段化决策

## 先确定必须优化什么

只比较会改变决定的真实维度：目标满足、实施成本/时间、团队实际能力、可靠性/安全/数据风险、可逆性、兼容/迁移、运维维护。不要固定制造十几个维度或无数据打分。

## 默认阶段

- **当下方案**：现在需要做、直接解决当前问题的最小充分改变。
- **后续演进**：只有负载、团队、产品阶段或约束达到明确条件时再增加。
- **理想方案**：只在帮助今天的边界设计或避免死路时展开。

后两项没有当前决策价值就省略。

## Trade-off 与推荐

写真实可验证取舍，不写“灵活性 8/10”这类伪精确评分。最终推荐明确为什么适合当前阶段、现在做什么、什么不做、什么条件出现后重评、如何验证有效。方向取决于尚未决定的业务/安全/数据硬条件时，再提请用户决定。
